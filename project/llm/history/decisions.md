# Decisions — Ключевые дизайн-решения

---

## 001 — Observation Space: относительные координаты

**Решение:** Observation = `(dist_to_goal, angle_to_goal)` вместо глобальных `(x, y, theta, gx, gy)`

**Почему:**
- Обобщается на произвольные позиции старта и цели без изменений сети
- Нейросеть не нужно учить игнорировать абсолютные координаты
- Меньше входов → проще модель → быстрее обучение

**Альтернативы:** глобальный стейт `(x, y, theta, gx, gy)` — отклонено, переусложнение

---

## 002 — Action Space: (v, omega) без динамики

**Решение:** Действие = `(v, omega)` — линейная и угловая скорость, применяется через кинематику Эйлера.

**Почему:**
- Кинематическая модель достаточна для BC на 2D задаче
- Не нужна динамика (масса, инерция) — цель учебная
- Проще реализовать и отлаживать

**Альтернативы:** управление моментами/силами — отклонено, излишне для учебного проекта

---

## 003 — Модель: Decision Transformer вместо BC (MLP)

**Решение:** Decision Transformer — GPT-like, принимает последовательность (RTG, obs, act).

**Почему:**
- Пользователь сам поставил задачу DT (переориентация проекта)
- DT позволяет управлять желаемым RTG при инференсе
- Интересно исследовать зависимость от размера датасета

**Альтернативы:**
- BC MLP — был исходным планом, отклонён в пользу DT
- DAgger — итеративный сбор данных, сложнее
- GAIL — adversarial, требует RL окружение

## 004 — Геометрический эксперт вместо двухфазного

**Решение:** Непрерывный геометрический контроллер на основе cross/dot product вектора позиции и heading.

**Почему:**
- Двухфазный (поворот → движение) — задокументирован в архитектуре, но реализован другой
- Геометрический даёт более плавные траектории
- Финальная фаза: при `dist < 0.015` переключается на PD по theta

**Сингулярность:** при `rp = 0` (heading ⊥ вектору на цель) `sign(0) = 0` → action = 0, робот стоит.
**Фикс:** добавлен `noise_std` в ExpertController.

## 005 — Obs и State в cos/sin представлении

**Решение:**
- obs: `[dist, cos(angle_to_goal), sin(angle_to_goal)]` — shape (3,)
- state: `[x, y, cos_theta, sin_theta]` — shape (4,)

**Почему:**
- Сырой угол имеет разрыв на ±π — нейросеть плохо обобщает через него
- cos/sin — непрерывное представление на окружности SO(2)
- Убирает класс сингулярных провалов при обучении

**Альтернативы:** сырой угол — отклонено из-за разрыва.

---

## 006 — Формат датасета: HDF5 per-trajectory

**Решение:** Каждая траектория — отдельная группа в HDF5. Поля: obs, actions, rewards, rtg, timesteps, terminals.

**Почему:**
- DT требует доступ к целым траекториям (RTG, timesteps)
- HDF5 эффективнее для разных длин траекторий чем padded numpy
- Субсеты (1k/2k/5k/10k) — отдельные файлы для экспериментов с размером датасета

## 007 — Предгенерация кэша в SequenceDataset

**Решение:** При инициализации предгенерируются все subsequences (`samples_per_traj=20`) и хранятся как numpy-массивы.

**Почему:**
- `num_workers=0` (Windows + Jupyter) — DataLoader не может параллелить
- С кэшем DataLoader просто индексирует массив, нет overhead на sampling
- GPU utilization поднялся с ~10W до ожидаемых 30+W
